# Rapport : stabilisation des tests instables

Branche `test/tests-instables`. Seuls des fichiers de test ont été modifiés. Le code de production n'a pas été touché.

## Reproduction

- Vitest, suite complète : 2 passes au réglage par défaut (1 échec US-013). Puis 4 passes à 24 workers sur 12 cœurs, avec d'autres suites d'agents qui tournaient sur le poste en même temps : 5 à 7 échecs par passe sur US-008 AC10, US-025 AC5, US-009 AC11, US-010 AC6, US-013, US-021, US-025 AC1, US-025 AC2 (lint).
- Playwright US-025 AC5 : non reproduit tel quel (10/10 verts, ni avec un ralentissement CPU ×8 par CDP). Cause démontrée par une sonde (voir plus bas).
- Go : cause démontrée par l'analyse de la fenêtre de temps (voir plus bas), correction vérifiée en charge.

## Causes et corrections

| Test                                                                                   | Cause                                                                                                                                                                                                                                                                                                      | Correction                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-008 AC10 (clavier), US-008 AC2, US-025 AC5, US-025 AC1                              | Le harnais `identityProviderHarness` gardait les délais par défaut : 5 s par test, 1 s pour `findBy`/`waitFor`, 1 s pour `vi.waitFor` dans `waitForNavigationTo`. Une connexion complète (2 montages de l'app + échange de jetons) suivie de 40 tabulations dépasse ces délais en charge.                  | Dans le harnais, même convention que les autres harnais du projet : `vi.setConfig({ testTimeout: 30000 })`, `configure({ asyncUtilTimeout: 5000 })`, et une limite explicite de 5 s pour `waitForNavigationTo`. Un délai plus long n'affaiblit aucune assertion positive.                                                                                                                                                     |
| US-008 AC10 et US-025 AC5 « Se déconnecter » au clavier                                | Après le retour de connexion, l'app place le focus sur le h1 de façon différée (comportement voulu par US-008 AC10). Si cet effet arrive pendant les tabulations, le focus repart du h1.                                                                                                                   | Nouvel helper `mainHeadingFocused()` (attente d'état : h1 focalisé), appelé après `signInAs` avant de tabuler.                                                                                                                                                                                                                                                                                                                |

## Preuves de stabilité

- Go : `go test -run 'TestUS024FiletDelaiCroissantAuxValeursDeProduction$' -count=20` : ok (231 s), lancé en parallèle d'une suite Vitest à 24 workers. `gofmt -l` : vide. `go vet` : ok.
- Playwright : `E2E_LANGUES=fr,en npx playwright test e2e/US-025/AC5-mise-en-vente-clavier.spec.ts --repeat-each=10` : 20/20 verts.
- Vitest : 5 passes complètes `npx vitest run` d'affilée, 540/540 vertes à chaque passe (157 à 216 s, sur un poste chargé par les suites d'autres agents). Lint US-025 AC2 : environ 8 s au lieu de 73 à 105 s.
- `npx tsc -b`, `npx eslint src e2e --max-warnings 0`, `npx prettier --check .` : verts.

## Points d'attention (hors périmètre, non corrigés)

- Le test US-025 AC2 écrit ses sondes dans `src/features/sonde-us025-<pid>`. Si un run est tué, le dossier reste dans `src` et casse `eslint src` (constaté une fois, supprimé à la main). Une piste serait un dossier sonde ignoré par git.
- Aucun instable ne vient du code de production.
